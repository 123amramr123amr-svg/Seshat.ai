# C Chat — منصة نماذج الذكاء الاصطناعي

منصة واحدة لتشغيل وإدارة إصدارات متعددة من النماذج. أول نموذج حاليًا هو **خوفو 1.0 (Khufu 1.0)**، ويعمل محليًا.

- اسم المنصة: **C Chat**
- النموذج الأول: **خوفو 1.0 (Khufu 1.0)**
- المطوّر: **عمرو أحمد** (Amr Ahmed)

البنية الأساسية مبنية بالكامل من الصفر — من غير أي نموذج جاهز: الـ Attention والـ LayerNorm
والـ Transformer والـ Tokenizer والتوليد كلهم مكتوبين بالإيد. التدريب بـ PyTorch، والتشغيل بـ NumPy بس.
ولما النموذج مايعرفش، المخ (brain.py) بيدور في النت وبيتعلم وبيقدر يرسم — وممكن كمان تربطه
بمخ خارجي بمفتاح API لو حبيت (اختياري تمامًا، شوف "المخ الجديد" تحت).

## تدريب اللغة وتطوير خوفو 1.0

أُضيف `pretrain.py` للتدريب اللغوي السببي (توقّع الحرف التالي) على نصوص عربية وإنجليزية، بدل الاكتفاء بتدريب السؤال والجواب. ضع ملفات UTF-8 بصيغة `.txt` داخل `data/corpus/`، ثم شغّل:

```bash
python pretrain.py --size tiny --block-size 512 --steps 3000 --batch-size 2 --ram-mb 450
python train_model.py --resume --out seshat_chet_model.npz --size tiny --steps 1500
```

- استخدم نصوصًا كتبتها بنفسك أو مواد من الملكية العامة أو بتراخيص تسمح صراحةً بالتدريب.
- ابدأ بـ `tiny` وميزانية ذاكرة منخفضة، ثم راقب خسارة التدريب والتحقق قبل تكبير النموذج.
- السياق الحالي مقاس **بالحروف** لأن الـ tokenizer الحالي حرفي؛ 512 تعني نحو 512 حرفًا، وليست 512 كلمة أو token من نوع BPE.
- زيادة السياق ترفع استهلاك الذاكرة بشكل كبير؛ لا ترفع الرقم لمجرد الوصول لرقم ضخم.
- التدريب كل ساعة لا يضيف معرفة تلقائيًا من غير بيانات جديدة ومراجعة نتائج. شغّل التدريب على جهاز مخصص بعد إضافة corpus موثوق، مع الاحتفاظ بنسخ checkpoints.

الواجهة أصبحت تحمل اسم **C Chat** وتعرض اختيار النموذج من كتالوج `models.py`. خوفو 1.0 هو النموذج الوحيد الموصول فعليًا الآن؛ الإصدارات المستقبلية لا تظهر كمتاحة قبل توصيل checkpoint ومحرك تشغيل حقيقي.

## بيعمل إيه

- بيتكلم عربي (مصري) وإنجليزي
- بيجاوب على معلومات عامة (مصر والتاريخ، علوم، جغرافيا، تكنولوجيا، برمجة)
- بيترجم كلمات بين العربي والإنجليزي
- بيحل جمع وطرح وضرب وقسمة — بأرقام كبيرة وكسور (المحرك بيحسب بنفسه فالناتج مضمون)
- بيكتب أكواد: Python و JavaScript و C و C++ و Java و SQL و HTML و CSS و Bash
- بيشرح مفاهيم البرمجة (الأخطاء، أنواع البيانات، الدوال، OOP، API، Big O…)
- **بيعدّل الصور** اللي تبعتهاله من زرار المرفقات: أبيض وأسود، تغبيش، توضيح، قلب، تدوير، قص،
  سيبيا، رسم رصاص، حواف، بكسلة، برواز… (38 تعديل، وينفع أكتر من واحد في نفس الجملة)
- **بيوصف الصور والفيديو** من البكسلات: الألوان الغالبة، الإضاءة، التباين، الوضوح، والحركة في الفيديو
- **مش لازم تكتب السؤال بالحرف**: بيدوّر على أقرب سؤال يعرفه ويرد عليه
- **بيفكر قبل ما يرد**: بيكتب الأول هو فهم السؤال على إنه إيه، وبعدين يرد
- **بيفهم السؤال حتى لو برّه معلوماته**: بيحدد نوعه (رأي؟ سعر؟ سؤال عن شخص؟ طلب تنفيذ؟ توقع؟…)
  وموضوعه، ويكوّن رد فيه الموضوع نفسه بدل جملة واحدة محفوظة — ولو الموضوع ينفع يتبحث عنه
  بيدوّر عليه في النت بالموضوع اللي فهمه
- **بيأدب مع أي لفظ خارج**: أي شتم بأي صيغة (حتى بالأرقام زي "ا7مق" أو بالإنجليزي) بياخد رد مؤدب "ربنا يسامحك"
- **بيدور في النت لما مش عارف**: ويكيبيديا و DuckDuckGo من غير أي مفتاح، والسؤال اللي برّه اللي اتعلمه بيتجاوب من النت
- **بيتعلم بنفسه**: أي حاجة بيجاوب عليها من النت أو من المخ الخارجي بتتخزن في ذاكرته، والمرة اللي جاية بيرد عليها من غير نت — وانت كمان تقدر تعلمه بيدوي: `علمني: س: اللعبة المفضلة لعمرو ج: الشطرنج`، ولو حاجة اتعلمت غلط امسحها: `انسى: اللعبة المفضلة لعمرو`
- **بيرسم صور**: "ارسم لي قطة بتنظر للقمر" — مجانًا ومن غير مفتاح. والأشكال البسيطة
  ("ارسم قلب أحمر") النموذج المحلي بيحاول يرسمها بنفسه مربع مربع جنب الصورة
- **مخ خارجي اختياري**: لو ضفت مفتاح API متوافق مع OpenAI، الردود بتشتغل بشبكة عصبية ضخمة بتجاوب على أي سؤال في الدنيا

## المخ الجديد (brain.py)

الرد بيخرج من طبقتين فوق بعض:

1. **النموذج المحلي** (engine.py + memory.py) — هو البداية: الهوية، الحساب، الأكواد، وكل اللي اتعلمه من البيانات.
2. **المخ** (brain.py) — لما النموذج مايعرفش:

| الخطوة | بيعمل إيه | محتاج مفتاح؟ |
|---|---|---|
| الأدب | أي لفظ خارج بأي صيغة → رد مؤدب | لأ |
| الحساب | جمع/طرح/ضرب/قسمة بأرقام كبيرة وكسور — الناتج مضمون | لأ |
| الرسم | "ارسم لي قطة" → صورة (pollinations.ai — صورة واحدة كل 45 ثانية مجانًا) | لأ |
| التعلم | يخزن كل حاجة جديدة في `data/learned.json` ويرد منها المرة الجاية | لأ |
| المخ الخارجي | أي خدمة متوافقة مع OpenAI ترد على أي سؤال | مفتاح اختياري |
| فهم السؤال | نوع السؤال + موضوعه → رد متكوّن منهم (رأي، سعر، توقع، طلب تنفيذ…)، والبحث بيتم بالموضوع | لأ |
| بحث النت | ويكيبيديا (مع فلتر لكيان النتيجة تكون عن الموضوع فعلًا) و DuckDuckGo | لأ |

### تربيط مخ خارجي (اختياري)

من الواجهة: زرار ⚙ فوق → حط المفتاح والـ Base URL واسم الموديل → حفظ.
المفتاح بيتخزن في `data/config.local.json` (مش بيترفع على جيت هاب ومش بيتعرض في أي رد).

أو من متغيرات البيئة قبل التشغيل:

```bash
export SESHAT_API_KEY="sk-..."        # المفتاح
export SESHAT_API_BASE="https://api.openai.com/v1"   # أي خدمة متوافقة مع OpenAI
export SESHAT_API_MODEL="gpt-4o-mini" # اسم الموديل عندهم
python app.py
```

أمثلة خدم متوافقة: OpenAI، GLM (bigmodel.cn)، DeepSeek، Groq، Gemini (بendpoint متوافق).
لو المفتاح مش موجود أو طلع غلط، المخ بيكمل تلقائي ببحث النت.

للتحكم في الحاجات التانية:

```bash
SESHAT_SEARCH=0 python app.py        # اقفل البحث في النت
SESHAT_LOCAL_ONLY=1 python app.py    # النموذج المحلي لوحده — سلوك النسخة القديمة
```

### طول السياق وحجم النموذج

لازم نفرّق بين حاجتين:
- **عدد معاملات النموذج (Parameters):** ده جزء أساسي من حجم قدرته وتكلفة تشغيله وتدريبه.
- **طول السياق (Context):** كمية النص اللي يقدر يعالجها في المرة الواحدة.

الـ tokenizer الموجود حاليًا حرفي، لذلك قيمة `block_size=512` معناها حوالي 512 حرفًا، مش مليون كلمة أو مليون token من BPE. رفع السياق يرفع استهلاك الذاكرة والحساب، والانتباه التقليدي تزيد تكلفته تقريبًا مع مربع طول السياق.

الوصول لنموذج عام ضخم بمستوى النماذج التجارية يحتاج بيانات مرخصة على نطاق هائل وموارد تدريب متخصصة. لذلك خطة C Chat هي تطوير نموذج محلي صغير قابل للتدريب والاستكمال، وقياسه على اختبارات لم يرها، ثم تحسين الـ tokenizer والبنية والحجم تدريجيًا بدل ادعاء قدرات غير موجودة.


## حالة النموذج الحالي

النموذج اللي في المستودع: 875 ألف معامل (حجم `tiny`)، اتدرب 28 ألف خطوة على CPU.
القياس بـ `python evaluate.py` (الرد بيتحسب صح لو مطابق بالحرف):

| النوع | صيغ اتدرب عليها | صيغ جديدة ماشافهاش |
|---|---|---|
| محادثة | 69% | 38% |
| معلومات | 79% | — |
| شرح برمجة | 67% | — |
| أكواد | 90% | 84% |
| ترجمة | 80% | — |
| عواصم | 83% | — |
| حساب | 100% | — |
| **الكل** | **86%** (2062 من 2403) | **65%** (113 من 175) |

- أسئلة الاسم والمطوّر: 62 صيغة صح من 64.
- أسئلة برّه اللي اتعلمه (30 سؤال ماشافهمش): 19 بيرد عليهم "لسه ماتعلمتش"، و11 بيرد عليهم رد غلط.
- في الحساب بيحسب صح دايمًا: النموذج بيفهم المسألة وبيحسب، ولو غلط في الناتج
  (زي الأرقام الكبيرة اللي ماتدربش عليها) المحرك بيحسبها بنفسه وبيصلح الرد —
  شوف خطوة الحساب في "إزاي بيشتغل" تحت.
- أضعف حاجة عنده: سؤال محادثة مكتوب بصيغة جديدة خالص.

تدريب أطول أو حجم أكبر (شوف `train_colab.ipynb`) بيحسّن الأرقام دي.

الأرقام اللي فوق للنموذج لوحده. في التشغيل الفعلي النموذج بيشتغل مع **ذاكرة الأسئلة**
(`memory.py`)، وده اللي بيطلع على 89 سؤال مكتوبين بصيغ مش موجودة في البيانات
و66 سؤال برّه اللي اتعلمه (`python evaluate.py --paraphrase`):

| | النموذج لوحده | النموذج + الذاكرة |
|---|---|---|
| صيغ جديدة: رد صح | 38 من 89 (43%) | 68 من 89 (76%) |
| صيغ جديدة: رد غلط | 21 | 3 |
| صيغ جديدة: قال مش عارف | 30 | 18 (في 10 منهم اقترح السؤال الصح) |
| برّه اللي اتعلمه: قال مش عارف | 33 من 66 (50%) | 58 من 66 (88%) |
| برّه اللي اتعلمه: رد برد غلط | 33 | 8 |

حدود التشابه في `engine.py` اتظبطت على نفس الأسئلة دي، فالأرقام على أسئلة تانية ممكن
تطلع أقل شوية. أي سؤال متخزن بالحرف (غير الحساب) بيترد عليه صح دايمًا.

## التشغيل السريع

المستودع فيه نموذج متدرب جاهز (`seshat_chet_model.npz`)، فمش محتاج تدرب عشان تجرب.

```bash
git clone https://github.com/123amramr123amr-svg/Seshat.ai.git
cd Seshat.ai
pip install -r requirements.txt
python app.py
```

وافتح <http://localhost:5000>

أو من التيرمنال من غير متصفح:

```bash
python chat.py
python chat.py "اكتب كود بايثون يجمع رقمين"
```

المتطلبات: Python 3.9 أو أحدث. التشغيل محتاج `flask` و `numpy` بس.

## التدريب

التدريب محتاج PyTorch (على جهازك أو Google Colab — مش على الاستضافة):

```bash
pip install -r requirements-train.txt
python train_model.py
```

التدريب بيحفظ النموذج في `seshat_chet_model.npz` كل شوية، فلو وقفته بـ Ctrl+C اللي اتعلمه مش هيضيع.

| الأمر | الاستخدام |
|---|---|
| `python train_model.py --size tiny --steps 12000` | جهاز ضعيف من غير كارت شاشة |
| `python train_model.py --size small --steps 8000` | CPU كويس |
| `python train_model.py --size medium --steps 15000 --ram-gb 8` | كارت شاشة |
| `python train_model.py --resume --steps 3000` | يكمل تدريب على نفس النموذج |
| `python train_model.py --resume --steps 100000 --minutes 30 --lr 0.0004` | جولة تدريب نص ساعة على نفس النموذج |
| `python train_model.py --no-holdout` | يدرب على كل صيغ الأسئلة (النسخة النهائية) |

- `--ram-gb` بيحدد الرام المتاحة للتدريب تقريبًا؛ قلله لو التدريب اتقفل لوحده.
- بعد أي تغيير في الحجم (`--size`) لازم تدريب جديد من غير `--resume`.
- في جولات التكملة خلي `--lr` قليل (0.0003 – 0.0004). الدقة بتنزل في أول الجولة وبترجع
  تعلى في آخرها لما معدل التعلم يقل، فمتوقفش الجولة في نصها.
- لو زوّدت بيانات فيها حروف جديدة، `--resume` بيكبّر المفردات لوحده.

### قياس النموذج

```bash
python tests.py                  # اختبارات سريعة للمكونات (من غير torch)
python evaluate.py               # النموذج لوحده: نسبة الردود الصح لكل نوع
python evaluate.py --paraphrase  # صيغ جديدة خالص: النموذج لوحده × النموذج + الذاكرة
python evaluate.py --paraphrase --show   # ويطبع الأسئلة اللي غلط فيها
python evaluate.py --draw        # الرسم: تركيبات اتدرب عليها × تركيبات شكل + لون جديدة
python evaluate.py --understand  # فهم الأسئلة: مواضيع عمره ما شافها (النوع، الموضوع، الجملة)
python evaluate.py --samples     # يطبع ردود على أسئلة تجريبية
python memory.py "مين اللي برمجك"   # أقرب 3 أسئلة في الذاكرة لأي جملة
```

أسئلة اختبار الصيغ الجديدة في `data/paraphrase_tests.py`. الملف ده للقياس بس: متنقلش
أسئلته لملفات البيانات.

## إعدادات الأمان

قبل نشر التطبيق على الإنترنت، اضبط متغير البيئة `SESHAT_ADMIN_TOKEN` بقيمة سرية طويلة وعشوائية. واجهة الإعدادات تطلب هذا الرمز عند حفظ إعدادات المخ، وترسله في ترويسة `Authorization: Bearer`؛ لا تضع الرمز داخل ملفات المشروع أو GitHub.

يمكن ضبط حد طلبات الشات بالمتغير `SESHAT_CHAT_RATE_LIMIT` (الافتراضي 30 طلبًا لكل عنوان IP خلال 60 ثانية)، وحد طول الرسالة بالمتغير `SESHAT_MAX_MESSAGE_CHARS` (الافتراضي 4000). محدد المعدل الحالي داخل كل عملية سيرفر؛ لو شغّلت أكثر من عامل أو نسخة، استخدم محددًا مشتركًا مثل Redis.

## الرفع على استضافة

التشغيل مش محتاج torch، فالنموذج بيشتغل على استضافات الرام فيها قليلة (حوالي 70 ميجا
بالنموذج والذاكرة). ارفع مجلد `data/` مع المشروع: ذاكرة الأسئلة بتتبني منه وقت التشغيل،
ومن غيره النموذج هيرد لوحده.

**Pella (pella.app):**

1. New → اختار **Flask**.
2. استورد المستودع ده من GitHub (أو ارفع الملفات).
3. ملف التشغيل: `app.py` — والمكتبات من `requirements.txt`.
4. لو الاستضافة بتحدد بورت معين، السيرفر بيقراه من متغير البيئة `PORT` (الافتراضي 5000).

**أي سيرفر تاني (VPS):**

```bash
pip install -r requirements.txt gunicorn
gunicorn -w 1 -b 0.0.0.0:5000 app:app
```

خليه worker واحد (`-w 1`) عشان النموذج ميتحملش في الذاكرة أكتر من مرة.
وفي استضافات بتقرأ ملف `Procfile`، المشروع جاهز ليها من غير أي إعداد.

```
    ├── unknown_questions.py  أسئلة برّه اللي اتعلمه (بيتدرب يقول عليها "مش عارف")
    ├── paraphrase_tests.py   أسئلة اختبار بصيغ جديدة (للقياس بس)
    ├── learned.json          (بيتولد وقت التشغيل) اللي النموذج اتعلمه بنفسه
    └── config.local.json     (بيتولد وقت التشغيل) إعداداتك — مش بيتحفظ على جيت هاب
```

## إزاي تعلّمه حاجات جديدة

كل ما البيانات تزيد النموذج يبقى أذكى. بعد أي إضافة لازم تدريب تاني.

**سؤال وجواب** — في أي ملف `.txt` جوه `data/` (أو اعمل ملف جديد):

```
س: صيغة السؤال الأولى | صيغة تانية | صيغة تالتة
ج: الرد
```

بالإنجليزي استخدم `Q:` و `A:`. كل ما تكتب صيغ أكتر لنفس السؤال، النموذج يفهمه أحسن.

**كود** — في `data/code_snippets.py`:

```python
add("python", "يحسب مساحة المربع", "calculate the area of a square", '''
side = 4
print(side * side)
''')
```

وأسئلة العربي والإنجليزي بتتولّد لوحدها.

**كلمة للترجمة أو عاصمة** — سطر جديد في `data/wordlists.py`.

**موضوع النموذج مش المفروض يرد عليه** — في `data/unknown_questions.py`. ولو علّمته
موضوع كان مكتوب هناك، شيله من الملف ده عشان ميتعلمش ردّين عكس بعض.

للتأكد من البيانات من غير تدريب:

```bash
python dataset.py
```

## إزاي بيشتغل

الرد بيطلع من حاجتين مكتوبين من الصفر وبيشتغلوا مع بعض:

**ذاكرة الأسئلة** (`memory.py`): كل سؤال في البيانات بيتحول لـ"بصمة" من كلماته ومقاطع
3 حروف جوه كل كلمة، وكل مقطع ليه وزن (النادر وزنه عالي). سؤال المستخدم بيتعمله بصمة
بنفس الطريقة وبيتقارن بكل الأسئلة، وبعدين بنراجع إن الكلمات المهمة في السؤال المتخزن
موجودة في كلام المستخدم. النتيجة: أقرب سؤال + نسبة تشابه من 0 لـ 100%.

**النموذج** (شبكة GPT): بياخد `<user> السؤال <bot>` ويكتب سطر تفكير بين `<think>`
و `</think>` فيه نوع السؤال والسؤال بصيغته الأساسية، وبعدين الرد حرف ورا حرف.

الخطوات لكل رسالة:

1. السؤال بيتنضف (توحيد الألف والهاء، حروف صغيرة، من غير علامات استفهام).
2. لو نفس السؤال متخزن بالحرف → بيرد على طول.
3. لو التشابه مع أقرب سؤال 60% أو أكتر → بيرد برد السؤال ده.
4. لو السؤال مسألة حساب → النموذج بيقرا المسألة في سطر التفكير، والمحرك بيتأكد إن
   الأرقام المتقرية هي نفسها اللي في السؤال، وبيحسب الناتج بنفسه وبيصلح الرد لو
   النموذج غلط فيه. ولو النموذج قرا الأرقام غلط خالص (زي أرقام 3 خانات)، المحرك
   بيقرا المسألة من السؤال نفسه ويحسبها — فالحساب بيبقى صح دايمًا طالما فيه
   مسألة واحدة نضيفة في السؤال.
5. لو التشابه بين 30% و 60% **والنموذج فهم السؤال بنفس المعنى** → بيرد (الاتنين متفقين).
6. لو التشابه 35% أو أكتر من غير اتفاق → بيسأل "تقصد: «…»؟" وزرار يبعت السؤال ده.
7. غير كده → السؤال برّه معلوماته: بيفهم نوعه وموضوعه ويكوّن رد عليهم (شوف "فهم الأسئلة" تحت)،
   والمخ بيكمل بالبحث في النت لو الموضوع ينفع يتبحث عنه.

مثال:

```
السؤال:   مين اللي عملك وبرمجك
التفكير:  أقرب سؤال أعرفه: «مين طورك» — تشابه 71% — والنموذج فهمه بنفس المعنى
الرد:     اللي طورني هو عمرو أحمد.
```

`/chat` بيرجّع مع الرد: `thinking` (سطر التفكير)، `source` (الرد جه منين: `memory` أو
`memory+model` أو `model` أو `none`)، `matched` (السؤال اللي اتطابق)، و `suggestion`.

لما الذاكرة هي اللي بترد، الرد بييجي من النص المتخزن في البيانات مش من توليد الشبكة.
الشبكة دورها هنا إنها تأكد الفهم لما التشابه يكون متوسط، وإنها تحل الحساب. الحدود
(60% و 30% و 35%) في أول `engine.py`. لتشغيل النموذج لوحده من غير الذاكرة:
`SESHAT_MEMORY=0 python app.py`.

التفكير بتاع الشبكة مش تفكير حر زي النماذج الكبيرة: هو خطوة فهم واحدة اتدربت عليها
(تصنيف السؤال وتحويله لصيغته الأساسية). مسافات الإزاحة في الكود (4 مسافات / مسافتين)
كل واحدة توكن واحد، فالنموذج مبقاش يعدّ المسافات حرف حرف.

### فهم الأسئلة اللي برّه معلوماته (`data/understanding.py`)

قبل كده أي سؤال برّه البيانات كان بياخد نفس الجملة ("لسه ماتعلمتش الرد…"). دلوقتي النموذج
بيتدرب يطلّع من السؤال حاجتين ويكتبهم في سطر التفكير: **النوع | الموضوع**، وبعدين يكوّن رد
فيه الموضوع. الموضوع بيتنسخ من السؤال حرف حرف، فالرد بيطلع صح على مواضيع عمره ما شافها:

```
السؤال:   ايه رايك في القهوه
التفكير:  رأي | القهوه
الرد:     بتسألني عن رأيي في القهوه. أنا نموذج ذكاء اصطناعي ومعنديش رأي شخصي ولا ذوق، فمقدرش أحكم على القهوه.
```

الأنواع: رأي، سعر، أخبار، موضوع، شخص، طريقة، كود كبير، اختيار، كتابة طويلة (دول فيهم موضوع)،
وتنفيذ على الجهاز، سؤال عن المستخدم، توقع، معلومة لحظية، قرار شخصي، سؤال مفتوح، طلب مؤذي،
كلام مش مفهوم (دول ردهم من نوعهم). في التدريب 2277 (نوع، موضوع) منهم مواضيع من حروف
عشوائية عشان النموذج يتعلم **ينسخ** الموضوع مش يحفظ قايمة مواضيع.

المحرك بيراجع فهم النموذج: الموضوع لازم يكون موجود فعلًا في السؤال. لو النموذج مطلعش فهم
سليم، قواعد القوالب (`understanding.detect`) بتحدد النوع والموضوع، وبعدها نوع أقرب سؤال شبهه.
`/chat` بيرجّع `kind` و `topic` و `understood_by` (`model-text` = النموذج كتب الجملة كلها صح،
`model` = النموذج فهم والجملة اتكوّنت من فهمه، `rules` = القواعد، `memory` = أقرب سؤال).

المخ (`brain.py`) بيكمل من الفهم ده: "موضوع" و"شخص" بيتبحث عنهم في النت **بالموضوع اللي اتفهم**
("كلمني عن كرة السلة" → بحث عن "كرة السلة")، والباقي (رأي، توقع، تنفيذ…) بيترد عليه بالجملة
المتكوّنة لأن البحث فيه بيجيب كلام ملوش علاقة.

ده مش توليد حر زي النماذج العملاقة: النموذج بيكوّن جمل جديدة من **قوالب اتعلمها + موضوع من
سؤالك**. مبيألفش معلومة مش عنده — لو معندوش المعلومة والبحث مجابهاش، بيقول كده عن الموضوع نفسه.

**مبيردش بإجابة سؤال تاني:** لو سؤالك نفس جملة سؤال يعرفه بس كلمة مهمة اتبدلت ("كم عدد سكان
الصين" × "عدد سكان مصر"، "مين اخترع التليفون" × "مين اخترع الصفر")، مبيردش برد السؤال اللي
يعرفه — بيعتبره سؤال عن معلومة مش عنده ويدوّر عليها في النت (`understanding.other_subject`).

### الرسم

النموذج بيرسم بنفس الطريقة اللي بيكتب بيها: حرف ورا حرف. الرسمة شبكة 12 × 12 رمز جوه
بلوك ` ```draw `، كل رمز لون (`.` فاضي، `R` أحمر، `G` أخضر، `B` أزرق، `Y` أصفر، `O` برتقالي،
`P` بنفسجي، `K` أسود، `M` بمبي، `N` بني، `W` أبيض)، والواجهة بتحوّلها لمربعات ملونة وتحفظها PNG.
المحرك بيراجع الرسمة قبل ما يعرضها: لازم تكون 12 × 12، والنموذج يكون فهم نفس الشكل
المطلوب، واللون يكون هو المطلوب. لو لأ بيقول إن الرسمة طلعت مش مظبوطة ومبيعرضهاش.
الأشكال والألوان في `data/drawings.py`؛ زوّد شكل جديد هناك ودرّب.

### الصور والفيديو (`vision.py`)

ده كود عادي مكتوب بـ NumPy، **مش شبكة عصبية**: النموذج (875 ألف معامل، بيقرا حروف) أصغر
بكتير من إنه يشوف صورة. اللي بيحصل:

1. المتصفح بيفتح الملف، يصغّر الصورة لـ 512 بكسل (والفيديو بياخد منه 12 لقطة صغيرة)، ويبعت
   البكسلات خام. عشان كده السيرفر مش محتاج Pillow ولا ffmpeg.
2. **الوصف**: كل بكسل بيتسمّى بلون (من درجة اللون والتشبع والإضاءة)، وبنحسب نسبة كل لون،
   متوسط الإضاءة، التباين، الوضوح (تباين لابلاس)، ولون التلت اللي فوق واللي تحت. في
   الفيديو بنقارن اللقطات ببعض عشان نعرف الحركة وتغيير المشهد.
3. **التعديل**: بندوّر في الجملة على عبارات التعديل المعروفة (العبارة الأطول الأول) ونطبقها
   بالترتيب. "جدا / أوي" بتقوّي التعديل و"شوية" بتخففه. التعديلات بتتراكم على آخر نسخة،
   و"رجعها زي ما كانت" بترجع للأصل.
4. الصورة المتعدلة بترجع PNG مكتوب بالإيد (zlib + CRC).

`/chat` بيقبل مع `message`: `image: {w, h, data}` أو `video: {duration, w, h, frames}`
(البكسلات RGBA بـ base64)، وبيرجّع `edited` (data URL) لو فيه تعديل. (`image` في الرد = رابط
الصورة المرسومة من خدمة الرسم.)

**عايزه يعرف اللي في الصورة بجد (قطة؟ عربية؟ كلام مكتوب؟):** `vision.py` بيقيس ألوان وإضاءة
بس ومبيتعرفش على الأشياء. لو ضفت مفتاح مخ خارجي لموديل بيشوف صور (زي `gpt-4o-mini`) من زرار ⚙،
أي سؤال عن الصورة ("ايه ده"، أو صورة من غير كلام) بيتبعت له هو (`brain.llm_vision`) ويرد
بوصف حقيقي. لو المفتاح مش موجود أو الموديل مبيشوفش صور أو الخدمة وقعت → بيرجع لوصف الألوان.
التعديل دايمًا محلي.

المحرك الافتراضي NumPy. لتشغيل نفس الملف بـ torch (مثلًا على كارت شاشة):

```bash
SESHAT_ENGINE=torch python app.py
```

## حدود النموذج

- النموذج المحلي صغير وبيتدرب على بيانات مكتوبة بالإيد، فهو بيجاوب على المواضيع اللي اتدرب عليها
  وصيغ قريبة منها. لما مش عارف، المخ بيدور في النت (ويكيبيديا و DuckDuckGo) — فالرد بيحسن
  جدًا بس بيكون مصدره بحث مش فهم عميق. عشان تفهم أي سؤال في الدنيا فعلًا: ضيف مفتاح مخ خارجي (شوف فوق).
- مبيفتكرش الرسايل اللي فاتت في نفس المحادثة — كل سؤال بيترد عليه لوحده.
- الرسم شبكة 12 × 12 مربع لأشكال محددة (10 أشكال × 8 ألوان + 6 رسومات ثابتة). مش صور
  واقعية: توليد صورة حقيقية محتاج نموذج أكبر بآلاف المرات وكارت شاشة.
- الصور والفيديو: بيوصفهم بقياسات على البكسلات (ألوان، إضاءة، حركة) وبيخمّن المنظر من
  الألوان بس. **مبيتعرفش على الأشياء ولا الناس ولا الكتابة اللي في الصورة**، ومبيسمعش صوت الفيديو.
- تعديل الصور فلاتر وعمليات هندسية على الصورة كلها. مبيعرفش "شيل الخلفية" أو "غيّر لون
  العربية" لأن ده محتاج يفهم اللي في الصورة.
- الصورة بتتصغّر لـ 512 بكسل قبل التعديل (عشان رام الاستضافة)، والفيديو بيتوصف بس ومبيتعدلش.
- خدمة الرسم المجانية بتسمح بصورة واحدة كل 45 ثانية، وأحيانًا بتبقى بطيئة أو مش متاحة — لما ده يحصل seshat بيقولك.
- البحث بيقرا ملخصات صفحات ويكيبيديا ونتائج بحث — مش بيفتح الصفحات ويدرسها (ده محتاج مخ خارجي).
